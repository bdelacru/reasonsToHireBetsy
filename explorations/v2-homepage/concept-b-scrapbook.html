How I work

Good engineering starts before implementation.

I zoom out before I zoom in.

Before I start changing code, I want to understand the user, the system around the change, and how we will know the solution is actually working.

I follow the problem across layers.

Sometimes the answer is in the UI. Sometimes it is an API, a database query, deployment configuration, or the logs.

I ask one more question.

A ticket can say “add search,” but the useful questions are what people need to find and what happens when the happy path is not enough.
